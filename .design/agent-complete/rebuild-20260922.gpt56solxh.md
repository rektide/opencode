# agent-complete current-tip rebuild

## Result

The feature was rebuilt from scratch on locked baseline `dcfe1ec7bd49`. The
August production hunk was not ported: upstream already supplies direct
completion-notice navigation. The new line adds only the two current gaps:

1. failed foreground subagent rows retain error expansion and expose a
   distinct `Open child` action; and
2. background completion notices show the child's frozen last-reported
   context occupancy when one exists.

The implementation follows the confirmed scope exactly: TUI first, no app
rendering change, metadata-only model visibility, no cumulative-token fallback,
and no zero or guessed measurements.

## Concern-grouped ladder

### 1. Pin terminal metadata — `11152be27423`

`test(core): pin subagent terminal metadata`

- Added an actual Session/Job integration test covering `completed`, `error`,
  and `cancelled` delivery through `SubagentCompletion.deliver`.
- Each terminal synthetic message is asserted to retain exactly
  `{ source, childID, agent, state }` and the expected unchanged synthetic
  text.
- This protects the navigation seam and gives the return-context rung a
  terminal-state matrix.
- Check at the rung: `packages/core` subagent suite **12 passed, 0 failed**;
  `bun typecheck` clean.

### 2. Freeze return context usage — `f215e8affce8`

`feat(core): freeze subagent return context usage`

- `SubagentCompletion.deliver` reads `Session.context(childID)` at delivery
  time and finds the latest assistant message carrying provider-reported
  tokens.
- `TokenUsage.total` sums input, output, reasoning, cache read, and cache write
  exactly once. A positive result is frozen as additive
  `metadata.contextTokens` beside the existing terminal metadata.
- Missing context, decode/read failure, no measured assistant, and non-positive
  totals all omit the field. Completion delivery itself still proceeds.
- `Session.Info.tokens` is never consulted; cumulative lifetime usage cannot
  masquerade as current context occupancy.
- The parent-model synthetic text remains byte-for-byte unchanged; the
  measured integration fixture records `117_000` only in metadata.
- Check at the rung: `packages/core` subagent suite **12 passed, 0 failed**;
  `bun typecheck` clean.

### 3. Open failed children — `1bd9c0ee0fc7`

`fix(tui): open failed subagent sessions`

- `InlineToolRow` accepts optional error-expanded action content without
  changing the row's existing click-to-toggle behavior.
- Failed subagent rows show `↳ Open child` below the expanded error. It uses
  semantic secondary-action colors, its own hover state, the existing
  selection guard, and stops event propagation before navigating.
- The action reads the already-projected `metadata.sessionID` and navigates
  through the same `{ type: "session", sessionID }` route as successful launch
  rows and completion notices.
- Real TUI fixture coverage proves both failed and cancelled rows first reveal
  their error, remain in the parent, and then navigate through the distinct
  action.
- Check at the rung: completion-notice fixture **6 passed, 0 failed**;
  `packages/tui` `bun typecheck` clean.

### 4. Render frozen usage — `2c1162f9d4b4`

`feat(tui): show subagent return context usage`

- `SessionNoticeMessageV2` validates positive finite `contextTokens` at the
  unknown metadata boundary.
- The muted suffix renders compact lowercase units such as `(117k ctx)`.
  Description truncation reserves the parenthetical's width so a narrow
  terminal does not discard the metric first.
- Missing, zero, malformed, and shell values render no parenthetical.
- The real notice fixture now covers completed notices at narrow and wide
  widths, errored and cancelled notices, unknown omission, navigation, and
  inert shell notices.
- Check at the rung: completion-notice fixture **9 passed, 0 failed**;
  `packages/tui` `bun typecheck` clean.

## Decisions and promotion posture

There were no deviations from the operator-confirmed defaults. Two details are
worth an operator eyeball before promotion:

1. The distinct open action appears only after expanding the failed row. This
   deliberately keeps the first click's existing post-mortem behavior and
   avoids navigating away while revealing an error.
2. Return-context measurement is best-effort. A context read failure omits the
   optional metric rather than suppressing the completion notice; it never
   substitutes cumulative usage.

App rendering remains a separate optional follow-up. The feature remains On
deck; inclusion in `working` requires the phase-2 promotion decision.
