## Part A — current-state map

All line references below are from `dcfe1ec7bd49`.

### Background completion notices: direct navigation now exists upstream

Upstream `735556eab8e0` (`fix(tui): open completed subagent sessions
(#49675)`) restored a **direct notice → child Session** path in the TUI after
`8d1a9799f4ef` had removed all completion-notice links:

- `packages/tui/src/routes/session/index.tsx:2016-2026` reads a `childID` only
  for `source === "subagent"`.
- `packages/tui/src/routes/session/index.tsx:2041-2064` brightens a subagent
  notice on hover, keeps shell notices inert, applies the text-selection
  guard, and routes directly to `{ type: "session", sessionID: childID }`.
- The click path has **no state predicate**. Given a `childID`, it works for
  `completed`, `error`, and `cancelled`, even though the regression at
  `packages/tui/test/completion-notices.test.tsx:130-195` currently exercises
  only `completed`. Error/cancelled parity is implemented but under-tested.
- `8d1a9799f4ef` is still accurately understood as the removal commit: it
  deleted `jumpToBackgroundTool`, `backgroundToolRowIndex`, hover, and the
  notice handlers. `#49675` later restored navigation in the simpler direct
  form rather than restoring jump-to-launch-row.

Core supplies the required ID for every background terminal state:

- `packages/core/src/session/subagent-completion.ts:28-43` handles every
  non-running `Job.Info` status, emits the terminal status in the synthetic
  text, and always persists
  `{ source: "subagent", childID, agent, state }`.
- `packages/core/src/session/subagent-job.ts:23-33` waits for the background
  job and delegates its terminal `Job.Info` to that delivery function.

Therefore the revived deliverable's notice-navigation portion already exists
upstream on the locked tip, including behavior for errored and cancelled
background children. The remaining work here is regression coverage, not a
replacement TUI implementation.

### Launch rows, scroll preservation, and foreground failures

Successful/running TUI launch rows already navigate:

- `packages/tui/src/routes/session/index.tsx:3173-3196` reads
  `props.metadata.sessionID` and routes to the child.
- `2960c61f9c5c` (`#47464`) remains effective after later tab changes:
  `packages/tui/src/context/session-tabs.tsx:356-369` keys scroll anchors by
  the exact parent/child Session ID, while `:322-325` clears the whole family
  only when its root tab closes.
  `packages/tui/src/routes/session/index.tsx:482-499` preserves/restores the
  selected Session's anchor.

The old beads diagnosis that core failure paths carry the child ID only in
message text is stale on this baseline. The current path is:

1. `packages/core/src/tool/plugin/subagent.ts:200-202` publishes tool progress
   `{ sessionID: child.id, status: "running" }` immediately after child
   creation.
2. `packages/core/src/session/runner/publish-llm-event.ts:544-553` retains that
   progress snapshot.
3. On tool failure, `publish-llm-event.ts:327-341` folds progress into the
   durable `session.tool.failed` metadata. Explicit `Tool.Error.metadata`
   would be merged over it; the generic metadata channel is already defined
   at `packages/schema/src/tool.ts:61-65`.
4. `packages/core/src/session/message-updater.ts:359-374` projects that
   metadata into the failed tool state.

This covers the explicit error/cancel result branches in
`packages/core/src/tool/plugin/subagent.ts:245-251` and interruption after the
progress event. The text still contains the child ID as a model-facing aid,
but it is no longer the only copy.

The actual remaining TUI gap is interaction, not persistence:

- `packages/tui/src/routes/session/index.tsx:2688-2754` makes a failed
  `InlineTool` clickable only to toggle its error expansion and returns before
  `props.onClick`.
- Consequently `Subagent`'s route callback at `:3193-3196` is unreachable on
  failure even though `ToolPart` reads failed-state metadata through
  `toolDisplayMetadata` (`:2461-2469`).

The app is closer to complete: its generic error branch reads the subagent
`metadata.sessionID` and gives the error card's subtitle an href/click handler
at `packages/session-ui/src/tools/tool-renderer.tsx:1199-1249`. Core's progress
snapshot makes this usable for current failures. A regression should prove
error and cancellation explicitly.

### Exact token-count substrate

The primary figure should come from the **latest provider-reported assistant
usage in the child's current context**, frozen when `SubagentCompletion.deliver`
builds the parent synthetic message:

1. Read `Session.context(childSessionID)`, not `Session.Info.tokens`.
   `packages/core/src/session.ts:139-141,370-373` exposes the compaction/revert-
   bounded context read.
2. Find the last `assistant` message with `tokens` in that context.
   `Session.Message.Assistant.tokens` is persisted at
   `packages/schema/src/session-message.ts:211-236`.
3. Those fields come directly from `session.step.ended`
   (`packages/schema/src/session-event.ts:348-363`) or a token-bearing `session.step.failed`
   (`:365-381`), projected into the assistant at
   `packages/core/src/session/message-updater.ts:261-283`.
4. Compute occupancy with `TokenUsage.total` — input + output + reasoning +
   cache read + cache write exactly once
   (`packages/schema/src/token-usage.ts:5-17`). This matches the existing TUI context recipe in
   `packages/tui/src/util/session.ts:45-77`.

If there is no post-compaction/revert assistant usage, or the total is not
positive, omit the additive metadata field. That is unknown, never zero. Do
not use `Session.Info.tokens` for this label: those are lifetime cumulative
totals (`packages/schema/src/session.ts:30-43`), updated by every token-bearing
step and selected auxiliary usage in
`packages/core/src/session/projector.ts:58-103,678-689`. Those totals are the
source consumed by session/tree quota totals, but answer a different question.

The clean insertion seam is
`packages/core/src/session/subagent-completion.ts:20-43`: expand its Session
capability from `synthetic` to `context`, measure immediately before admission,
and add a positive numeric field such as `contextTokens` beside
`childID`/`agent`/`state`. Leave the synthetic text unchanged for the default
human-only policy.

## Recommended recreate-afresh ladder (operator ruling required)

Follow the term-v2 2026-09-03 precedent: preserve the August snapshot and
start an unbookmarked, concern-grouped line directly on `dcfe1ec7bd49`. Do not
port the old TUI hunk.

1. **`test(core): pin subagent terminal metadata`** — prove that error,
   cancellation, and interruption retain the progress-derived child
   `sessionID`; prove all synthetic terminal states carry `childID`. This
   records what upstream now makes possible and catches any actual parity gap
   before changing production.
2. **`feat(core): freeze subagent return context usage`** — measure the last
   positive assistant usage from `Session.context` at delivery and persist
   `contextTokens` in synthetic metadata. Cover measured, post-compaction/no-
   anchor, and no-step failure cases. Synthetic text remains unchanged.
3. **`fix(tui): open failed subagent sessions`** — preserve click-to-expand
   error behavior and add a distinct navigate affordance using the persisted
   `sessionID`; handle cancelled children identically. Avoid making one click
   both navigate away and expand an error the user cannot read.
4. **`feat(tui): show subagent return context usage`** — append a compact
   `(117K ctx)`-style parenthetical from `contextTokens`, omit unknown, and
   reserve its width while truncating the description so the metric is not
   the first content lost on narrow terminals. Extend the existing completion-
   notice test across `completed | error | cancelled`, narrow/wide layouts,
   shell inertness, navigation, and unknown omission.
5. **Optional app parity commit** — if the operator wants the new count on all
   human surfaces, render it in
   `packages/session-ui/src/timeline/session-timeline-row.tsx` and restore
   focused component/E2E coverage for terminal notice links. App navigation
   itself needs no rebuild.
6. **Docs/rebuild record** — replace stale current-behavior claims with the
   upstream map, record the chosen field/surface/model-visibility contracts,
   and only then place `agent-complete-20260922` plus floating
   `agent-complete` at the passing new tip.

## Operator decisions before rebuilding

1. **Surface scope** — TUI only (the revived patch's historical scope), or
   TUI + app token parenthetical for human-surface parity? Navigation already
   exists on both.
2. **Model visibility** — recommended default: metadata/rendering only. Do not
   append the count to synthetic text seen by the parent model unless an
   explicit model-use case outweighs prompt noise.
3. **Metric field contract** — recommended minimal field:
   `contextTokens: number`. Do not add cumulative lifetime tokens unless the
   UI will expose and clearly distinguish them.
4. **Failed-row interaction** — recommended distinct `Open child` affordance
   while the row itself keeps toggling error expansion; reject a single click
   that expands and immediately navigates away.
5. **Formatting** — accept existing `Locale.number` uppercase units
   (`117.0K ctx`) or add a notice-local lowercase compact form matching the
   requested example (`117k ctx`).
