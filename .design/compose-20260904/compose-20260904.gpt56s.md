## Friction

### Dependency installation

The required baseline `bun install` resolved dependencies but failed the
`tree-sitter-powershell@0.25.10` postinstall: that release supplied no matching
prebuild and node-gyp ran under Node 26.6.0. A local
`bun install --ignore-scripts` completed linking without changing `bun.lock`;
the repository consumes the package's WASM asset rather than its native binding.

After term-v2 entered the tree, its `@effect/platform-node` dev dependency
needed one more `--ignore-scripts` link pass. This is the important procedural
distinction: install once after locking upstream to freshen baseline
dependencies, but permit another explicit link pass when a carried feature
changes a dependency manifest or a concrete missing-module error proves it is
needed. The final build must remain `--skip-install`.

The isolated composition workspace then built cleanly, but the canonical
`~/src/opencode-working` checkout retained its own older `node_modules`. Its
first host build completed the web archive and failed at CLI bundling because
`@opencode-ai/util/runtime-import` was not linked. One explicit
`bun install --ignore-scripts` installed three packages without changing
`bun.lock`; the immediate build retry passed. This confirms that dependency
state is workspace-local even when jj history and build inputs are shared.

### Source-of-truth corrections

Two small bookkeeping defects were repaired or recorded rather than allowed to
distort the composition:

- `subagent-recovery` contains 14 commits. Its refresh report says 13 in some
  prose, but the actual source revset and explicit commit list both say 14.
- A committed jj-vcs correction sat one commit above the floating bookmark.
  The floating `jj-vcs-rektide` bookmark was fast-forwarded from `5f3998cc` to
  `fba4c1dc` before duplication. Immutable `jj-vcs-rektide-20260903` remains at
  `5f3998cc`.

### Tool residue and mutation pipes

The app typecheck emitted untracked
`packages/storybook/playwright/{config,story}.d.ts` declarations during the
jj-vcs proof. They are tsgo build residue, not client generation or feature
content, and were removed rather than committed. Incremental state did not emit
them again during the final gate.

One accidental double-pipe killed an initial `jj duplicate` invocation with
SIGPIPE. Jujutsu's transaction committed nothing, and the subsequent invocation
created exactly one complete stack. The standing rule remains: never pipe a jj
mutation command into `head` or another early-closing consumer.

## Eases

- Prefer `jj duplicate -A <composition-tip> -r <source-range>` for clean
  stacks: it directly inserts the duplicates and rebases the empty working copy,
  reducing stale-id handling between duplicate and rebase operations.
- Count source ranges from the DAG before dispatch and treat that count as
  authoritative when maintenance prose has drifted.
- Keep generated-client checks and app declaration-residue checks separate;
  both can write files, but only `packages/client/src/**` belongs to client
  regeneration.
