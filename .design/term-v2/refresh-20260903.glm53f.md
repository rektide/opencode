### Adaptation (API drift, in scope)

Upstream's host-resolution refactor (`ed3259a9`) renamed/reshaped the
plugin source contract `PackageResolver.resolve(spec) → string|undefined`
into `PackageSource.prepare(spec, install?) → { directory }`. The
feature's three fixture sites were adapted, assertions unchanged:

- `test/app-lifecycle.test.tsx` ×2: `packages: { resolve: async () =>
  undefined }` → `packages: { prepare: async () => ({ directory: "" }) }`
  (upstream's own test idiom).
- `test/fixture/app-lifecycle-process.ts`: `resolve: async () =>
  pathToFileURL(plugin).href` → `prepare: async () => ({ directory:
  path.dirname(plugin) })` — the fixture's tmp dir already follows the
  new host convention (`index.ts` + `tui.ts`), so `Host.resolve`
  discovers the same plugin content.

## Process incidents (disclosed)

- **First rebuild round lost in flight**: the test file
  `app-lifecycle.test.tsx` was restored wholesale from the old feature
  version instead of using the 3-way union — the resulting diffstat delta
  (+522 vs +283) exposed it; redone from the merged union.
- **`jj abandon | head` SIGPIPE**: piping `jj abandon` output through
  `head` killed the op after printing but before its transaction
  committed — the abandon printed "Abandoned 2 commits" yet the DAG kept
  them, and a fixup commit landed after the docs commit. This is the same
  lesson patches.md records for `jj duplicate | head`; **never pipe jj
  mutation commands through head** (re-learned the hard way). Redone with
  output redirected to a file and the DAG verified at each step.
- **Empty-working-copy tree loss**: after a successful abandon, the empty
  `@` re-parents and takes the parent's tree — retained working-copy
  content is dropped if the only copy lived in abandoned commits.
  Recovered by restoring from the abandoned tree by commit-id
  (`abbd0eb311dd`), which stays addressable.
