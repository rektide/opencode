## The halted session (2026-09-23 00:24–00:55 EDT) — third incident, root-caused

The first attempt composed pulse/term-v2/subagent-recovery/export-qa
cleanly, then jj-vcs-rektide halted ~4-of-35 commits in with
non-mechanical conflicts. The resolution review's central finding: the
session was rebasing **stale 09-05-era jj-vcs copies, not the freshened
bookmark line** (`a3225c9c`, refreshed 2026-09-22). Mechanically provable
from the conflict-marker sides (`xzyypnul 44518b01`, `sroourus 58b3dc41`):
they carry `SystemPromptPlugin`/`VariantPlugin` imports as context —
modules removed upstream by `#48943` (`2226afaea5`, 2026-09-14) — and the
landed content used the pre-`a5312e169b` `@opencode-ai/*` scope (migrated
2026-09-07). No ancestor of the compose base contains those imports; the
source was pre-freshen. That is why this feature conflicted
non-mechanically for the third time. Standing lesson (now enforced): a
compose session must verify the source bookmark/commit of each feature
line *before* rebasing — `jj log -r <feature-bookmark>` plus a content
spot-check.

  `init`).

Two cleanup mechanics discovered the hard way:

1. **`jj abandon` rebases visible descendants onto the abandoned commit's
   parents** — it does not hide them. Abandoning the stale tail's five
   named commits first rebased 57 orphan-chain descendants onto the live
   export-qa tip `1c9490f9` as a wall of CONFLICT commits beside the live
   stack. Recovery: enumerate the garbage exactly
   (`1c9490f95d11:: ~ ::@`, minus the two preserved strays) and abandon
   it *atomically* so nothing remains to rebase. Standing lesson: always
   abandon a dead line's whole descendant closure in one call.
2. **Workspace working-copy auto-recreation.** The empty heads on feature
   tips are the live feature workspaces' `@` commits. Abandoning one makes
   jj mint a fresh empty `@` for that workspace on the same parent — the
   population regenerates one-per-workspace no matter how many rounds you
   sweep. Steady state is irreducible; stop after confirming each parent
   has exactly one empty child (`children(<tip>)`).

### `bun run generate` — validation passed, but the composed tree cannot run it ⚠

**Prominent flag.** From `packages/client` with `@` at the final tip,
`bun run generate` **crashes**:
`GenerationError: Conflicting Effect type reference: string`
(`httpapi-codegen` `effectTypeReferences`, index.ts:478).

Root cause, proven by experiment: jj-vcs commit `4c65a12163cd` ("test
(schema): preserve identifiers and omit absent Jujutsu fields") reorders
`Project.Vcs` from upstream's
`Schema.String.check(isPattern).annotate({ identifier })` to
`Schema.String.annotate({ identifier }).check(isPattern)` — needed to
satisfy `contract-hygiene.test.ts`'s top-level
`ast.annotations?.identifier` assertion for `Project.Vcs`. The
annotate-first AST makes the codegen derive the document name `string`
for that reference, colliding with another `string`-named reference
(e.g. plain `Provider.Package = Schema.String`) and tripping the
conflict guard. The freshened feature line carries the same order — this
is a **latent break on the feature line itself** (generate was last run
there before the reorder landed; later client types were deferred).

Verified both directions, working copy restored after each:

- Composed order (feature intent): generate **crashes**.
- Upstream order (temporary flip): generate **exit 0**, and the only
  working-copy diff is the flip itself — **the generated client is
  byte-identical to committed**, which validates the hand-chained
  drizzle schema stamp `b473bfa3` (prevId `e98619ef`) and the m46/m47/m48
  registry union. The flip also fails the feature hygiene test
  (1 fail in `contract-hygiene`), i.e. the two intents genuinely collide.

Resolution is an operator decision, not patched here: (a) teach the
codegen to skip the anonymous-name collision check for
identifier-resolved references (upstream-shaped fix, smallest semantic
footprint), (b) revert the reorder and amend the hygiene assertion, or
(c) find a third schema shape satisfying both. Until decided, any future
`bun run generate` on this tree will crash — the regen-rider path in the
compose procedure is blocked by this.

## Store situation (CIFS-backed shared repo)

- **Missing commit object `ad5e582e…`** in dead op-log material. It is
  absent git-side too (read-only `cat-file -e` probe — never `cd` into
  the shared repo). Effect: any revset enumeration that walks into it
  dies mid-render (`heads(::)`, set-difference templates), producing
  **silently truncated listings** — both forward and reversed renders
  stop at the poison, and stderr suppression hides it. `children()`
  proved unreliable while garbage surrounded it, reliable again after
  the atomic abandons. One unrenderable head remains reachable only
  through the missing object: left in place, unreachable and harmless.
  Practical rule for this store: never trust a single enumeration;
  render both directions, union, and per-commit spot-checks for anything
  you act on.
- **Phantom `.tool-versions` dirent** at the shared repo root
  (42 bytes, `??????????` permission bits on CIFS): breaks default-
  workspace snapshotting and `mise`. This is why all jj work must run

## Lessons promoted / recommended

1. Verify each feature line's source bookmark and content era before
   rebasing (third stale-source incident; cheap check, expensive miss).
2. Compose difficulty-ascending (recorded in `patches.md` 2026-09-23) —
   this run's order already reflects it.
3. Abandon dead lines atomically including their whole descendant
   closure; `jj abandon` rebases survivors, it does not hide them.
4. Empty unbookmarked heads on feature tips are live workspaces' `@` —
   they regenerate; the steady state is one per workspace.
5. Schema-annotation reorders are codegen-visible: any commit touching
   `.annotate({ identifier })` placement must run
   `bun run generate` before landing (new standing gate candidate).
6. Never deploy a composition that has not passed its battery — the
   `202609230451` partial-candidate deploy repeated the 09-04 class of
   incident with a different contract.
